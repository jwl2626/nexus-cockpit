# 工程说明：为什么这样分层

这篇讲「怎么改」，`README.md` 讲「怎么用」。

---

## 1. 数据流

```text
configs/*.json
      │
      ▼
   Config  ──────────────────────────────┐
      │                                  │
      ▼                                  │
  build_data()                           │
      │  train / val / test              │
      ▼                                  │
  DataLoader × 3                         │
      │                                  │
      ▼                                  │
   fit()  ──► train_one_epoch() ──┐      │
      │           evaluate(val)   │      │
      │                           ▼      │
      │                     history{}    │
      │                                  │
      ├──► runs/*/best.pt ───────────────┘（含 config，可自还原）
      │
      ▼
   evaluate(test)
      │
      ├──► 混淆矩阵 / 每类 P/R/F1 ──► report.txt
      └──► 错例拼图 ───────────────► misclassified.png

best.pt ──► export_torchscript() ──► model.pt（脱离本工程也能跑）
        └─► Predictor ────────────► 单图推理
```

**关键约定：`engine.py` 不关心数据是什么，只关心「给它一个 DataLoader」。**
所以你换成座舱特征向量，engine 一行不用改。

---

## 2. 模块职责与扩展点

| 模块 | 职责 | 改这里能干什么 |
| --- | --- | --- |
| `config.py` | 所有超参的唯一来源 | 加超参：加一个字段，`_coerce` 自动处理类型 |
| `data.py` | 数据集与增强 | 换成自己的数据：改 `build_data()` 返回 `DataBundle` |
| `models.py` | 模型与注册表 | 加模型：写个 `nn.Module`，注册进 `MODELS` |
| `engine.py` | 训练循环 | 改优化器策略、加梯度累积、加 EMA |
| `metrics.py` | 指标 | 加 F1-macro、AUC、自定义业务指标 |
| `checkpoint.py` | 存取 | 加版本号、加推理预处理参数 |
| `export.py` | 导出 | 加 ONNX |
| `predict.py` | 推理 | 加批量推理、加 TTA |
| `cli.py` | 入口 | 加新子命令 |

## 3. 怎么加一个新模型

```python
# models.py
class BigCNN(nn.Module):
    def __init__(self, hidden: int = 256, dropout: float = 0.25):
        super().__init__()
        ...  # 注意保持 forward 输入 (N,1,28,28)，输出 (N,10)

MODELS["big"] = BigCNN
```

然后命令行就能用：

```bat
python -m mnist_torch.cli train --model big --config configs/cnn.json
```

**不用改的地方**：engine、metrics、checkpoint、export、predict、cli 的其余逻辑。
因为 `build_model()` 统一按名字取，`checkpoint` 里存了 config，还原时自动知道用哪个结构。

> 新模型记得跑一次 `run_smoke.bat`——它会走一遍导出和推理，能抓出 `forward` 里的形状错误。

---

## 4. 怎么加一个新指标

以「宏平均 F1」为例：

```python
# metrics.py
def macro_f1(report: dict[str, dict]) -> float:
    return sum(item["f1"] for item in report.values()) / len(report)
```

在 `cli._report_test()` 里打印即可。

**不要**把指标算在 `engine.py` 里：engine 负责训练，metrics 负责评估，混在一起以后没法换指标。

## 5. 迁移到非图像数据（你的座舱场景）

三步：

### 第一步：改 Dataset

```python
class VectorDataset(Dataset):
    """输入已经是特征向量，不需要 transform。"""
    def __init__(self, X, y):
        self.X = torch.tensor(X, dtype=torch.float32)   # (N, D)
        self.y = torch.tensor(y, dtype=torch.long)      # (N,)

    def __len__(self):
        return len(self.y)

    def __getitem__(self, i):
        return self.X[i], self.y[i]
```

### 第二步：改模型输入维度

```python
class DiagMLP(nn.Module):
    def __init__(self, n_features: int, n_classes: int, hidden: int = 64, dropout: float = 0.2):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_features, hidden), nn.ReLU(), nn.Dropout(dropout),
            nn.Linear(hidden, n_classes),
        )
    def forward(self, x):
        return self.net(x)
```

### 第三步：关掉图像相关的增强

`build_transform()` 里的 `RandomAffine` 对向量没有意义，换成加高斯噪声或者干脆不做。

**其余全部复用。** 这就是分层的价值。

## 6. 训练技巧速查（MNIST 适用）

| 症状 | 调整 |
| --- | --- |
| loss 不降 | lr 调大 10 倍试试；检查标签有没有错位 |
| loss 变 NaN | lr 太大，或者没做归一化 |
| 训练准、验证差 | 加 dropout / weight decay；减少参数量 |
| 收敛太慢 | 换 Adam；加 lr scheduler |
| 卡在 99% 上不去 | 你的数据和模型已经到瓶颈了，继续调参收益极小——这是 MNIST 的正常天花板 |

**关于 lr**：Adam 下 1e-3 是安全的起点，1e-2 容易炸，1e-4 会慢。
**关于 batch**：128 是 MNIST 的甜点，256 在 1070Ti 上更快但精度略降。

---

## 7. 为什么不用 PyTorch Lightning / TensorBoard

不是它们不好，是**这个工程的目的不同**：你要看懂每一行为什么这么写。

- 用 Lightning，20 行就训完，但你不知道 `optimizer.step()` 在哪、早停怎么实现；
- 用 TensorBoard，多一个依赖，而且你要的是「看得见的日志」，不是「点开网页看曲线」。

等你能闭着眼写出 `engine.py`，再上这些工具，那时它们是加速器，不是黑盒。
