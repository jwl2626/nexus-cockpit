# NEXUS COCKPIT 座舱诊断台架 · 产品架构方案

**版本** V1.0 ｜ **范围** 座舱域控 DV 阶段诊断 / 台架自检 / 老化温循执行
**形态** 一套「软件 + 台架硬件 + 测试方案」的可交付产品

---

## 0. 定位与边界

| 做 | 不做 |
| --- | --- |
| 座舱域控的功能诊断、日志解析、8D 报告 | 整车级 HIL 仿真 |
| 台架外设接入自检与老化执行 | 量产 EOL 产线节拍设备（可裁剪复用） |
| CAN/以太/串口/USB 多通道联合诊断 | 自研 CAN 卡、自研采集卡（一律用货架件） |
| 测试用例编排与结果归档 | 替代功能安全认证（只提供证据，不替代流程） |

**一句话**：把「一个工程师的调试脚本」变成「一台能交付、能复用、能追溯的诊断台架」。

## 1. 总体架构

```
┌──────────────────────── 应用层（Web） ────────────────────────┐
│  诊断台（三域/12 模块） │ 台架测试台 │ 8D 报告 │ 设备档案 │ 设置 │
└───────────────────────────────┬───────────────────────────────┘
                                │ HTTP + SSE（单端口 8790）
┌───────────────────────────────▼───────────────────────────────┐
│                      bench-agent（本地服务）                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ 调度器    │ │ 用例引擎  │ │ 规则引擎  │ │ 报告引擎  │          │
│  └────┬─────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘          │
│       └────────────┴────────────┴────────────┘                │
│                   事件总线（Event Bus）                        │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ Channel Adapters: adb │ fastboot │ pcui │ can │ eth │      │ │
│  │                   ngx │ audio │ rf │ power │ chamber      │ │
│  └──────────────────────────────────────────────────────────┘ │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ Storage: SQLite（session / measurement / event / case）    │ │
│  └──────────────────────────────────────────────────────────┘ │
└───────────────────────────────┬───────────────────────────────┘
                                │ USB / CAN / ETH / 串口 / 模拟
┌───────────────────────────────▼───────────────────────────────┐
│                        台架硬件（货架件）                       │
│  主控工控机 │ CAN 卡 │ 网卡/打流 │ 采集卡 │ 声卡 │ 串口 │ 电源 │ 温箱 │ 综测仪 │
└───────────────────────────────────────────────────────────────┘
```

**三个关键决策**

1. **单进程单端口**：一个 `bench-agent` 管所有通道，不再 can/bench 各起一个服务；
2. **事件总线 + 落盘**：所有通道产出统一事件，先入库再从库查询，页面刷新不丢；
3. **通道插件化**：新增硬件只写一个 `BaseChannel` 子类 + YAML 配置，不改内核。

## 2. 硬件选型

### 2.1 选型原则

| 原则 | 说明 |
| --- | --- |
| **能用货架件就不自研** | CAN 卡、采集卡、声卡、电源全部采购成熟型号，自研只做「转接板/线束」 |
| **接口冗余** | USB 口数量按「外设数 × 1.5」配置，避免 Hub 级联掉线 |
| **可替换** | 每个外设都能单独换品牌，软件侧通过通道适配层隔离 |
| **分级配置** | 便携台 / 标准台 / 老化台三档，客户按预算选 |

### 2.2 主控（核心计算单元）

| 档位 | 推荐 | 配置 | 说明 |
| --- | --- | --- | --- |
| 标准台 | 工控机（研华 IPC-510 / 研扬 ARK-3532） | i7-12700 / 32GB / 1TB NVMe / 6×USB3 / 2×千兆网 / 1×PCIe | 可插采集卡，7×24 稳定 |
| 便携台 | 迷你主机（Intel NUC / 联想 Tiny） | i5 / 16GB / 512GB / 4×USB3 / 2×网口 | 现场用，成本低 |
| 老化台 | 同标准台 | + UPS | 老化 24h 不能断电 |

> **不自研主板/SoC**：诊断工具的价值在软件与流程，自研主控只会增加维护成本。
> 若客户要求国产化，可换飞腾/鲲鹏工控机，agent 是 Python，跨架构无压力。

## 3. 软件系统架构

### 3.1 分层

| 层 | 组件 | 职责 |
| --- | --- | --- |
| 表现层 | 诊断台 / 台架页 / 报告页 / 设置 | 只做展示与交互，不含业务逻辑 |
| 接口层 | REST + SSE（127.0.0.1:8790） | 命令下发、事件推送 |
| 业务层 | 调度器、用例引擎、规则引擎、报告引擎 | 编排、判定、生成 |
| 通道层 | 10 个 Channel Adapter | 封装具体硬件协议 |
| 存储层 | SQLite（WAL 模式） | 会话、测量、事件、用例结果 |
| 系统层 | 日志、配置、权限、升级 | 横切能力 |

### 3.2 通道插件接口

```python
class BaseChannel:
    id: str
    def open(self, cfg: dict) -> bool: ...
    def close(self) -> None: ...
    def exec(self, cmd: str, args: dict) -> Result: ...   # 一次性命令
    def stream(self) -> Iterator[Event]: ...              # 持续数据（日志/帧/打流）
    def selfcheck(self) -> CheckResult: ...                # 台架自检
```

新增硬件 = 一个子类 + 一段 YAML，不改内核。

### 3.3 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `device` | sn, model, fw, hw, bench_id | 样机档案 |
| `session` | id, device_sn, operator, start, end, mode | 一次测试会话 |
| `measurement` | session_id, channel, metric, value, unit, ts | 时序测量 |
| `event` | session_id, code, severity, module, ts, evidence | 异常事件 |
| `case_run` | session_id, case_id, round, result, detail, ts | 用例执行 |
| `audit` | ts, operator, action, target, before, after | 刷机/NV 等写操作 |

### 3.4 用例配置（YAML）

```yaml
id: wifi_toggle_10
name: WiFi 开关 ×10（每次重启）
category: stability
loop: 10
reboot_each: true
steps:
  - channel: adb
    cmd: shell svc wifi disable
    expect: {exit: 0}
  - channel: adb
    cmd: shell svc wifi enable
    expect: {exit: 0, timeout_s: 5}
criteria:
  pass: fails == 0
  evidence: [logcat, dumpsys wifi]
```

### 3.5 部署形态

```
NEXUS-Cockpit-Setup.exe
  ├─ bench-agent.exe        （PyInstaller 打包，免 Python）
  ├─ web/                   （静态站点，本地加载）
  ├─ config/                （通道配置、阈值表、用例）
  ├─ db/                    （SQLite，随使用增长）
  └─ docs/                  （手册、接线图）
```

双击启动 → 托盘图标 → 浏览器自动打开 `http://127.0.0.1:8790`。

### 3.6 权限与审计

| 角色 | 权限 |
| --- | --- |
| 操作员 | 自检、运行用例、看报告 |
| 工程师 | + 刷机、写 NV、改阈值、导数据 |
| 管理员 | + 用户管理、通道配置、升级 |

所有写操作（flash / writenv / 改阈值）进 `audit` 表，带操作前后值。

## 4. 测试台架装备

### 4.1 拓扑

```
        ┌──────────── 座舱域控（DUT）────────────┐
        │ USB0 → ADB      PCUI → 串口            │
        │ USB1 → Fastboot  CAN_H/L → CAN 卡       │
        │ ETH  → 镜像交换机 → 主控网口            │
        │ 屏/摄像头 → 解串板 → 采集卡             │
        │ 喇叭/MIC → 声卡                         │
        │ 12V ← 程控电源（+ 示波器监测）          │
        └────────────────────────────────────────┘
```

### 4.2 接线自检清单（每次上电必做）

| # | 检查项 | 判据 |
| --- | --- | --- |
| 1 | 电源电压 | 12.0 ± 0.2V，纹波 ≤ 100mVpp |
| 2 | CAN 终端电阻 | 断电测 60Ω ± 5Ω |
| 3 | USB 枚举 | `adb devices` 与 `fastboot devices` 均可见 |
| 4 | 以太链路 | `ethtool` 1000M 全双工，ping 网关 ≤ 1ms |
| 5 | 串口回环 | AT 返回 OK |
| 6 | 采集卡 | 抓一帧非全黑 |
| 7 | 声卡 | 1kHz 回环，THD+N ≤ 1% |
| 8 | 接地 | 台架与 DUT 共地，阻抗 ≤ 0.1Ω |

### 4.3 环境要求

- 供电：独立 220V 回路，配 UPS（老化台 ≥ 2kVA）
- 接地：单点接地，避免地环流
- 布线：CAN 双绞 + 终端电阻；音频屏蔽单端接地；USB 线 ≤ 3m 带磁环
- 温箱：DUT 与线束留 ≥ 50mm 风道，传感器贴外壳与 SoC 附近

## 5. 测试方案

### 5.1 测试分层

| 层 | 内容 | 时长 | 判据 |
| --- | --- | --- | --- |
| L1 冒烟 | 8 类外设自检 + 启动 | 5min | 全绿 |
| L2 功能 | 12 模块诊断 + 关键用例 | 1h | 无 P0 失败 |
| L3 压力 | SOC/DDR/UFS 应力 | 2–8h | 无重启/UE/IO 错 |
| L4 老化 | 用例循环 + 温箱 70/85°C | 48–96h | 全程无异常 |
| L5 温循 | -40↔85°C 循环 + 每段抽检 | 3–5 天 | 功能不失效 |

### 5.2 执行流程

```
接样机 → 建档案（SN/固件） → 接线自检 → L1 冒烟
   → 选套件（冒烟/全量/老化） → 执行（自动落库）
   → 异常自动截图/抓包/存日志 → 生成报告 → 归档/上传
```

### 5.3 老化编排

- 温箱按曲线升温 → DUT 上电 → 启动 agent 自动跑 L4 套件
- **每 4h 巡检**：截图、音频、CAN、心跳、温度、功耗
- **每 5min 落一次测量**，断档 > 10min 判异常
- 失败即告警（企业微信/邮件/声光），并保留现场（不重启，先取证）

### 5.4 判定阈值来源

统一来自 `docs/MONITORING-SPEC.md`（12 模块 × 指标 × 阈值 × 权重），
用例 YAML 只引用指标名，不改数值——换项目只换 spec。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 厂商接口迟迟不给（NGX/MCU/AT） | 用例只能模拟 | 先做 adb/fastboot/CAN 三条真实链路，其余留钩子 |
| 综测仪/温箱客户无预算 | 老化做不全 | 分级配置，先交便携台，后续扩展 |
| 现场网络受限（不能起服务） | 页面打不开 | agent 内置静态服务，纯本地 127.0.0.1 |
| 客户 IT 禁止装 exe | 部署失败 | 提供便携版（解压即用）+ 免安装说明 |
| 长时间老化内存泄漏 | 中途崩溃 | 关键进程守护 + 每轮用例后回收，加 72h 长稳测试 |
