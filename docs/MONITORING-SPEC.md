# 智能座舱域控 · 模块诊断与监控方案（V2.0）

> 目标：接入真实设备后，每个模块都能给出**可解释的健康分**与**可定位的异常事件**，
> 而不是把模拟数据换成随机数。本文定义采集、判据、评分、告警、展示五层。

---

## 一、总体架构

```
设备侧 Agent（座舱内）
  ├─ Android 层：adb shell / dumpsys / getprop / logcat / sysfs / procfs
  ├─ HAL 层：Camera、Audio(A2B)、Display(SerDes)、Power
  ├─ MCU/安全岛：串口或 SPI 诊断通道（心跳、ADC、看门狗、故障码）
  └─ 车载网络：CAN(FD) / 以太网(DoIP、TSN)
        │
        ▼  采样 → 归一化（单位、时间戳、设备拓扑）
   上传通道：MQTT / WebSocket / HTTP 批量上报（离线可缓存）
        │
        ▼
   规则引擎（确定性判据） + 时序库（指标历史）
        │
        ▼
   诊断网站：模块健康分 → 事件时间轴 → 8D 报告
```

**三条原则**

1. **规则优先，模型补充**：阈值/状态判断必须是确定性的（能写进验收标准的），统计模型只做趋势与关联。
2. **每个指标必须可回溯**：`值 = 采集命令 + 原始输出 + 时间戳`，报告里能点开看到原始证据。
3. **采样分层**：快变指标（CPU/温度）1–5s，慢变指标（UFS 寿命、坏块）5–30min，静态项（版本、配置）开机一次。

## 二、模块划分（业界通用 12 类）

| # | 模块 | 覆盖范围 | 主要风险 |
|---|---|---|---|
| 01 | SoC 计算核心 | CPU 12 核 / GPU / NPU / 频率与负载 | 过热降频、算力不足、锁死 |
| 02 | 内存 DDR | 容量、带宽、ECC、通道 | 泄漏、ECC 飙升、带宽打满 |
| 03 | 存储 UFS | 容量、坏块、寿命、延迟 | 写放大、坏块扩散、IO 卡死 |
| 04 | 显示监控区 | 仪表/中控/副驾/后排/HUG、SerDes | 黑屏、花屏、链路失锁 |
| 05 | 音频与 A2B | 功放、扬声器、MIC 阵列、A2B 环 | 无声、爆音、节点掉线 |
| 06 | 摄像头与感知输入 | 前视/环视/DMS/OMS、ISP | 掉帧、绿屏、链路丢锁 |
| 07 | 连接与射频 | WiFi / BT / 4G-5G / NFC / UWB | 断连、RSSI 恶化、天线故障 |
| 08 | 电源与热管理 | 12V 输入、电源轨、温控策略 | 欠压、过温、热关机 |
| 09 | MCU 与安全岛 | 心跳、ADC、看门狗、锁步、故障码 | 心跳丢失、误复位、安全降级 |
| 10 | 系统稳定性 | panic / ANR / crash / 重启 / 启动时长 | 崩溃循环、启动变慢 |
| 11 | 诊断与 OTA | UDS、DoIP、版本一致性、升级成功率 | 刷写失败、版本错配 |
| 12 | 时间同步与网络 | PTP/gPTP、以太网链路、TSN | 时间跳变、链路抖动 |

> 与现有网站映射：01–09 对应 CDC 域现有卡片，10 为「稳定性」，11–12 建议新增两个卡片（本次先出规范，UI 后续加）。

## 四、健康分模型

```
模块健康分 = 100 − Σ(指标扣分 × 权重系数)
指标扣分 = 0（正常）/ 10（警告）/ 25（严重）/ 40（致命）
权重系数 = 该指标权重 / 100
```

- **平滑**：单点抖动不直接扣分，需连续 N 个采样（默认 3）超限才计。
- **恢复**：指标回到正常并保持 5min，扣分按 50% 回补/次，避免“一次抖动终身带病”。
- **域分**：该域所有模块分的加权平均（权重 = 模块重要性：安全岛 1.5、SoC/存储 1.2、其余 1.0）。
- **整机分**：三域按 0.5 / 0.3 / 0.2 加权（座舱为主）。

等级：≥ 90 健康｜80–89 关注｜60–79 异常｜< 60 严重｜出现致命项直接判「需维修」。

## 五、告警分级与处置

| 级别 | 判据 | 展示 | 处置 |
|---|---|---|---|
| L1 提示 | 单指标轻微越界 | 时间轴蓝点 | 记录，纳入趋势 |
| L2 警告 | 持续越界或权重 ≤ 15 指标异常 | 黄点 + 卡片角标 | 巡检、观察 24h |
| L3 严重 | 高权重指标异常或功能降级 | 红点 + 域分下降 | 48h 内定位，出 8D |
| L4 致命 | 安全岛失锁、看门狗复位、黑屏 | 顶部横幅 + 声音告警 | 立即停用，现场处理 |

## 六、与诊断网站的映射

| 采集层 | 规则层 | 展示层 |
|---|---|---|
| `signals.{module}.{metric}` | 阈值表（本文第三节） | 模块卡片的 3 个关键指标 |
| 原始输出（可选） | 事件生成（code + severity） | 时间轴、详情页 |
| 拓扑（设备路径） | 关联分析（跨模块） | 8D 报告 D2/D4 |

**事件码规范**：`{模块}_{指标}_{类型}`，如 `DISP_SERDES_UNLOCK`、`UFS_IO_ERROR`、`MCU_HB_MISS`。

## 七、接入真实设备的最小集（第一周就能做）

1. **SoC/内存/存储/稳定性**：纯 Android 命令，`adb shell` 即可，无需 vendor 支持 —— 先做这 4 个模块，能覆盖 60% 的现场问题。
2. **热与电源**：`thermal_zone`、PMIC 节点（需 BSP 提供路径）。
3. **显示/音频/摄像头**：需要 HAL 或寄存器访问，找供应商拿接口文档。
4. **MCU/安全岛**：串口协议，需硬件同事配合定义帧格式。
5. **CAN/以太网**：沿用现有 `cockpit-diag` 的 checks 配置，扩到本文指标。

---

## 八、验收标准

- 每个指标有明确的采集命令与单位，误差可复现；
- 注入式验证：人为制造 10 类故障（欠压、降频、失锁、坏块、心跳丢、ANR、断网、过温、黑屏、时间跳变），系统须在 3 个采样周期内捕获并给出对应事件码；
- 健康分与人工判定一致率 ≥ 90%；
- 任一 L3/L4 事件可一键生成 8D，且证据链完整。
